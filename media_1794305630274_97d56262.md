Model the **existing Kayseri tram network** and a clearly labeled **hypothetical/proposed Erkilet scenario** in one interactive digital-twin application.

## Fundamental evidence rules
1. DO NOT invent station coordinates, station orders, timetables, passenger counts, travel times, shared segments, or real-time telemetry.
2. Label each value `verified`, `derived`, `assumed`, `scenario`, or `unknown`; distinguish observational timestamp from data validity date.
3. Every verified external factual claim requires URL + access date and, when available, publication/effective date. Record contradictory sources without silently merging them.
4. The user-supplied Bülbülpınarı → Havalimanı → AGÜ → Cumhuriyet Meydanı → Millet Bahçesi waypoints are **project scenario**, not a certified official route, stop list, or stop coordinates.
5. Existing T1–T4 services and proposed Erkilet scenario must NEVER share status `operational` by default.
6. Model station identity, line-station membership, directional trips, physical rail segments, and shared rail sections **separately**. Shared station != shared track segment.
7. Headway recommendations must identify inputs, optimization objective, assumptions, constraints, and whether demand is observed or synthetic.
8. Do not claim live tracking unless an authorized, working real-time data feed is connected. Show clearly marked simulated operation otherwise.

## Workflow
1. Start from one task ID in `docs/07_tasks.md`.
2. Research → Architect → Coding → Test; use slash commands or call subagents one by one.
3. Only give each agent the relevant files; avoid pasting full browsing transcripts into coding prompts.
4. Never replace the user's existing `app.py`, datasets, source code, or documentation without first examining them and getting approval for destructive overwrites.
5. Each coded task gets a runnable verification and a concise update in `docs/09_progress.md`.
6. Do not push to remotes, delete project files, modify unrelated files, or install dependencies without appropriate permission.
7. API keys, credentials, and secrets stay in environment variables and are never written to Markdown or committed.

## Tests
- Core initial data check: `python -m unittest discover -s tests -v`.
- Do not weaken tests to disguise a defect; independently report unresolved issues.
- Passing example tests does not mean the application itself is implemented or verified.

## Response style
- Turkish, concise technical explanation.
- Cite files and source URLs with specific facts.
- At the end state changed files, tests actually run, unresolved assumptions, next action.
